Варианты использования
        В данном разделе представлены варианты использования (use-case) системы для
описания сценариев, в которых может быть использована система, а также для
дальнейшего      написания   требований,       основывающихся      на   этих    вариантах
использования.


1. Стандарт на описание вариантов использования

        Все описания вариантов использования (use-case) должны иметь следующую
структуру:

 Номер                                         В формате UC-<N>, где N - натуральное
                                               число

 Название                                      В   формате     глагол-существительное,
                                               должно описывать достижимую цель и
                                               объяснять смысл сценария

 Актор                                         Действующее лицо, кто-то или что-то
                                               вне системы, влияющий на неё или
                                               находящийся под её влиянием.

 Цель                                          Краткое описание, чего Актор хочет
                                               достигнуть      с      этим     вариантом
                                               использования

 Предусловия                                   Условия,     которые     должны      быть
                                               выполнены для того, чтобы выполнялся
                                               сценарий

 Триггер                                       Событие, инициирующее          выполнение
                                               сценария

 Результат                                     Новый объект или изменение состояния
                                               существующего       объекта,      который
                                               показывает, что Актор достиг своей цели



                                           3
 Основной поток                             Типичный последовательный порядок
                                            пронумерованных шагов

 Расширения                                 Исключения из шагов основного потока,
                                            которые требуют отдельной обработки


        “Основной поток” представляет собой сценарий варианта использования,
включающий основные шаги и имеющий линейную структуру.
        “Расширения”   представляет   собой    дополнения      к   сценарию     варианта
использования, включающий расширения, исключения, альтернативные потоки.


2. Сценарии вариантов использования

2.1. UC-1. Запустить проект

 Актор                                      Разработчик

 Цель                                       Протестировать         написанный      код,
                                            запустив его в качестве исполняемого
                                            файла на сервере

 Предусловия                                Написанный код хранится в Удалённом
                                            репозитории GitLab
                                            На сервере запущен кластер Kubernetes


 Триггер                                    Разработчику     необходимо       запустить
                                            написанный код

 Результат                                  Проект запущен на сервере из исходного
                                            кода, написанного Разработчиком




                                        4
Основной поток                      1. Разработчик указывает в Системе
                                       репозиторий,     код    с   которого
                                       необходимо       преобразовать     в
                                       исполняемые файлы и запустить
                                    2. Система       отправляет    код    с
                                       удалённого       репозитория      на
                                       исполнение в кластер Kubernetes
                                    3. Система сообщает пользователю
                                       об успешном запуске кода

Расширения                       1а. При невозможности получить доступ
                                 к указанному пользователем удалённому
                                 репозиторию система сообщает об этом
                                 пользователю    и     даёт   возможность
                                 указать репозиторий ещё раз
                                 2а. При отсутствии связи с кластером
                                 Система    сообщает     пользователю    о
                                 невозможности запустить Проект
                                 3а. При возникновении ошибки при
                                 развёртывании проекта (ошибка при
                                 сборке, при запуске), Система сообщает
                                 об этой ошибке вместе с результатами
                                 работы Kubernetes в виде логов.


2.2. UC-2. Обновить проект

Актор                            Разработчик

Цель                             Протестировать изменения, сделанные в
                                 исходном коде, запустив новую версию
                                 кода в качестве исполняемого файла на
                                 сервере

                     Проекта

Триггер              Разработчик      отправляет       сделанные
                     изменения в удалённый репозиторий
                     GitLab

Результат            Развёрнутая версия Проекта заменяется
                     новой,     собранной    из    новой версии

                              Проекта и развернуть Проект из

                        3. Система сообщает пользователю
                              об успешном обновлении Проекта

Расширения           2а. При отсутствии связи с кластером
                     Система      сообщает       пользователю   о
                     невозможности запустить Проект
                     3а. При возникновении ошибки при
                     развёртывании Проекта (ошибка при
                     сборке, при запуске), Система сообщает
                     об этой ошибке вместе с результатами
                     работы Kubernetes в виде логов.

2.3. UC-3. Откатить проект

Актор                            Разработчик

Цель                             Развернуть Проект из более старой
                                 версии исходного кода, остановив все
                                 работающие сервисы этого Проекта

Предусловия                      Уже     развёрнута     некоторая       версия
                                 рассматриваемого Проекта

Триггер                          Обнаружена       ошибка,         требующая
                                 возвращения развёрнутого Проекта в
                                 одно из предыдущих состояний

Результат                        Развёрнутая версия Проекта заменяется
                                 новой, собранной из более старой версии
                                 исходного        кода,          написанного
                                 разработчиком

Основной поток                      1.
                                         Пользователь сообщает системе о
                                         необходимости                заменить
                                         развёрнутой Проект предыдущей
                                         версии         с          указанием
                                         идентификатора        этой     версии
                                         (хеш-кода коммита в удалённом
                                         репозитории,       соответствующего
                                         этой версии)
                                    2. Система        сообщает        кластеру
                                         Kubernetes     о     необходимости
                                         остановить все сервисы старого
                                         Проекта и развернуть Проект из
                                         другой   (более старой) версии
                                         исходного кода

                                           3. Система сообщает пользователю
                                              об успешном обновлении Проекта

Расширения                           1а. При невозможности получить доступ
                                     к указанному пользователем удалённому
                                     репозиторию        с     указанной    версией
                                     исходного кода, Система сообщает об
                                     этом пользователю и даёт возможность
                                     указать введённые данные ещё раз
                                     1b.      В     случае,     если      указанная

                                     версия       исходного    кода,   из которой

                                     сообщает об этом пользователю и не
                                     обновляет Проект.
                                     2а. При отсутствии связи с кластером
                                     Система       сообщает     пользователю     о
                                     невозможности запустить Проект
                                     3а. При возникновении ошибки при
                                     развёртывании Проекта (ошибка при
                                     сборке, при запуске), Система сообщает
                                     об этой ошибке вместе с результатами
                                     работы Kubernetes в виде логов.


2.4. UC-4. Просмотреть метрики

Актор                                Разработчик/Аналитик/DevOps-инженер

Цель                                 Узнать состояние развёрнутого Проекта,
                                     количество используемых физических
                                     ресурсов и пр.

Предусловия                          Рассматриваемый Проект уже развёрнут



                                 8
Триггер              Актор запрашивает у системы метрики
                     определённого Проекта

Результат            Актор получает метрики системы в
                     графическом представлении, а также
                     логи   системы      в    текстовом      виде
                     (подробнее о составе метрик и формате
                     логов см. Требования к ПО)

Основной поток          1. После         получения         запроса
                            пользователя                  Система
                            запрашивает                   метрики
                            развёрнутого Проекта и логи его
                            сервисов через API Kubernetes,
                            метрики физической машины, на
                            которой развёрнут Проект через
                            Node-exporter.
                        2. Система преобразует полученные
                            данные в графический формат и
                            отображает       их       пользователю
                            (подробнее            о        составе
                            отображаемых          данных       см.
                            Требования к ПО)

Расширения           1а. В случае невозможности получения
                     данных от одного из внешних сервисов
                     Система сообщает пользователю об этой
                     ошибке и отображает те данные, которые
                     получилось получить (или ничего, если
                     не удалось получить данные ни от одного
                     из внешних сервисов)

2.5 UC-5. Ограничить ресурсы

Актор                               Разработчик/DevOps-инженер

Цель                                Ограничить       физические        ресурсы
                                    сервера,       доступные          Проекту,
                                    развёрнутому на этом сервере

Предусловия                         Рассматриваемый Проект уже развёрнут

Триггер                             Рассматриваемый     Проект     потребляет
                                    слишком много физических ресурсов или
                                    наоборот     сообщает    о     недостатке
                                    ресурсов

Результат                           Проект получает больше или меньше (в
                                    зависимости от цели Актора) физических
                                    ресурсов

Основной поток                         1. Актор посредством интерфейса
                                          сообщает          Системе          о
                                          необходимости              обновить
                                          настройки               ограничений
                                          физических        ресурсов       для
                                          рассматриваемого Проекта
                                       2. Система, посредством Kubernetes
                                          API сообщает кластеру Kubernetes
                                          о      необходимости       обновить
                                          ограничения физических ресурсов
                                          для      развёрнутого       Проекта,
                                          предварительно переведя данные,
                                          полученные от пользователя в
                                          вид, пригодный для Kubernetes
                                       3. Система сообщает пользователю
                                          об      успешном        обновлении
