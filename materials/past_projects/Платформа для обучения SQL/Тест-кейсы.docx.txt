2.1.1 Тест-кейс 1. Валидация введенной информации в форму регистрации
Проверяемые требования: 1-01-BE-002
Описание: проверка процесса валидации введенной информации в форму регистрации
Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: 
	•	пользователь не авторизован
	•	пользователь зашел на страницу регистрации
	•	пользователь видит форму регистрации
Шаги:
Ожидаемый результат:
Пользователь вводит фамилию в поле 1.1.1 на английском языке или спец-символы или числа 
Отображается уведомление красного цвета под полем 1.1.1 о неправильности введенной информации в поле 1.1.1
Пользователь вводит имя в поле 1.1.2 на английском языке или спец-символы или числа 
Отображается уведомление красного цвета под полем 1.1.2 о неправильности введенной информации в поле 1.1.2
Пользователь вводит некорректный (несоответсвующий шаблону) email в поле 1.1.4
Отображается уведомление красного цвета под полем 1.1.4 о неправильности введенной информации в поле 1.1.4
Пользователь вводит пароль в поле 1.1.5 и далее вводит другой (отличающийся от первоначального) пароль в поле 1.1.6
Отображается уведомление красного цвета под полем 1.1.5 о несовпадении введенной информации в поле 1.1.5
Пользователь вводит уже существующий логин в поле 1.1.3
Отображается уведомление красного цвета под полем 1.1.3 о уже используемом логине другим пользователем

	•	Поле для ввода:  Ваше имя (1.1.1)
	•	Поле для ввода: Ваша Фамилия (1.1.2)
	•	Поле для ввода: Логин (1.1.3)
	•	Поле для ввода: Email (1.1.4)
	•	Поле для ввода: Пароль (1.1.5)
	•	Поле для ввода: Повторение пароля (1.1.6)
и чекбоксом - Флаг: Я администратор (1.1.7)
Пользователь находится на странице, URL которого содержит /registration
Отображается кнопка 1.1.8 - регистрация нового пользователя

Письмо о подтверждении регистрации отображается в общем списке писем сервиса почты

2.2.2 Тест-кейс 5. Основные действия при аутентификации
Проверяемые требования: 2-02-BE-003, 2-02-FE-003, 2-03-BE-004
Описание: проверка основных действий при аутентификации
Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: 
пользователь не авторизован
пользователь зашел на страницу аутентификации
Шаги:
Ожидаемый результат:
Пользователь заполнил данными поле логина (поле 2.1.1) и поле пароля (поле 1.2.2) и нажал на кнопку 2.1.3 - “Войти”
Отображается состояние загрузки под кнопкой 2.1.3 - “Войти”
Пользователь ввел неверные данные для аутентификации в поле логина (поле 2.1.1) или поле пароля (поле 1.2.2) и нажал на кнопку 2.1.3 - “Войти”
Отображается уведомление красного цвета в виде уведомление, сообщающее о неправильности набранной информации или о несуществовании данного пользователя
Пользователь ввел верные данные для аутентификации в поле логина (поле 2.1.1) или поле пароля (поле 1.2.2) и нажал на кнопку 2.1.3 - “Войти”
Осуществляется редирект на страницу профиля пользователя, URL которого должен содержать /users/
Пользователь нажимает на кнопку 1.2.4 - “Зарегистрироваться”
Осуществляется редирект на страницу с формой регистрации, URL которого должен содержать /registration/

2.3.1 Тест-кейс 6. Отображение основных данных на странице пользователя
Проверяемые требования: 3-01-DE-001, 3-01-FE-002, 3-01-FE-003
Описание: проверка отображения основных ui-элементов и информации на странице профиля пользователя
Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: пользователь авторизован
Шаги:
Ожидаемый результат:
Пользователь заходит на страницу своего профиля
Пользователь видит страницу профиля (интерфейс 3), URL которой содержит строку /users/
Пользователь переходит на вкладку “основные данные”
Пользователь видит основную информацию о его роли: бейдж “ученик” в случае, если пользователь является учеником и “администратор” - если пользователь имеет роль администратора
Пользователь переходит на вкладку “основные данные”
Пользователь видит основную информацию его учетной записи - содержатся следующие поля:
	•	Поле с данными: Имя (3.1.1)
	•	Поле с данными: Фамилия (3.1.2)
	•	Поле с данными: Логин (3.1.3)
	•	Поле с данными email (3.1.4)
Пользователь вводит текст в любое поле (3.1.1, 3.1.2, 3.1.4)
Поля 3.1.1, 3.1.2, 3.1.4 доступны для редактирования - удалить полностью текст, содержащийся в поле, ввести новый текст в поле

2.3.2 Тест-кейс 7. Редактирование профиля пользователя
Проверяемые требования: 3-01-FE-004, 3-01-FE-005, 3-01-FE-006, 3-01-BE-008
Описание: проверка механизма редактирования профиля пользователя
Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: 
	•	пользователь авторизован
	•	пользователь зашел на страницу профиля
Шаги:
Ожидаемый результат:
Пользователь переходит на вкладку “основные данные”
На странице отображается кнопка “Сохранить” (3.1.5)
Пользователь переходит на вкладку “основные данные” и еще не редактирует ни одно из полей 3.1.1, 3.1.2, 3.1.4
На странице редактирования профиля кнопка “Сохранить” (3.1.5) имеет неактивное состояние 
	•	нет возможности кликнуть на нее, а при клике ничего не должно происходить
	•	0.5 < opacity < 1, где opactity - прозрачность кнопки
Пользователь редактирует одно из полей 3.1.1, 3.1.2, 3.1.4 - вводит новый текст, отличный от содержащегося в поле ранее
На странице редактирования профиля кнопка “Сохранить” (3.1.5) имеет активное состояние (при клике кнопку создается возможность сохранить измененные данные)
(Одно из полей 3.1.1, 3.1.2, 3.1.4 изменено) Пользователь кликает на кнопку “Сохранить “ (3.1.5)
В случае успешного сохранение пользователь должен увидеть уведомление зеленого цвета с текстом “Данные успешно обновлены”
(Пользователь обновил данные) Пользователь перезагружает страницу
Обновленные ранее (перед перезагрузкой страницы) данные установились в полях 3.1.1, 3.1.2, 3.1.4

2.4.1 Тест-кейс 9. Отображение общей информации на странице статистики
Проверяемые требования: 4-01-DE-001, 4-01-DE-002
Описание: проверка отображения общей информации и ui-элементов на странице статистики
Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: 
	•	пользователь авторизован
	•	пользователь зашел на страницу профиля пользователя
Шаги:
Ожидаемый результат:
Пользователь переходит на вкладку статистики на странице профиля пользователя
Отображается страница статистики (интерфейс 4), URL которого содержит /?tab=statistics
Пользователь переходит на вкладку статистики на странице профиля пользователя
Страница статистики отображает блок “Общая статистика”  со следующей информацией (в том числе число, определяющее метрику):
	•	количество решенных задач
	•	количество начатых задач
	•	кол-во пройденных курсов
	•	общее количество баллов

Тип проверки: ручное тестирование, автоматизированные интеграционные тесты
Предусловия: 
	•	пользователь не авторизован
	•	пользователь зашел в каталог мини-курсов/задач

Шаги:
