Требования к системе “Цифровой помощник электрика”
1. Введение
1.1. Постановка задачи
В рамках энергосистемы существует проблема поддержания оптимального баланса между запасами электроэнергии и нуждами потребителей таким образом, чтобы не было ни переизбытка, ни недостатка энергии. Этого можно достичь, оперативным управлением потоками электроэнергии в городской среде. С ростом городской инфраструктуры остро встает вопрос об оптимальном распределении электроэнергии ввиду того, что, если потребитель тратит меньше электроэнергии чем планировалось или больше чем планировалось, это несет убытки для энергетических компаний. На данный момент эта проблема решается с помощью агрегаторов электроэнергии, однако агрегаторы являются дополнительной прослойкой между потребителем и поставщиком, что может негативно сказаться на качестве достижения поставленной цели. Выходом может являться применение системы умного энергораспределения для городской среды. В редких случаях агрегаторы могут использовать специализированное программное обеспечения для управления. В зарубежных энергосистемах внедрение механизма управления спросом позволило организовать централизованное управление ресурсами потребителей, что позволяет потребителям уменьшать платежи за электроэнергию на 0,6-1,7%

1.2. Цель
Требуется реализовать программное обеспечение для управления и контроля электроэнергии в городской среде, с целью оптимизации энергопотребления, включающее в себя:

Рабочее место электрика: 
	•	удаленное управление реле автоматически (системой) или в ручном режиме.
	•	контроль состояния источников питания (исправен/неисправен).
	•	контроль количества потребляемой электроэнергии каждым пользователем. 
Рабочее место администратора:
	•	просмотр списка пользователей и контроль их показателей.
	•	отключение пользователей от системы. 
Интерфейс пользователя:
	•	просмотр сведений об энергопотреблении, стоимости энергии и статуса оплаты. 
	•	получение отчетов о всех показателях.

1.3. Область действия
Система рассчитана для небольших объектов, жильцов многоквартирных домов, среднее количество пользователей которых не более 100.

1.4. Определения и сокращения
1.1. Цифровой помощник электрика (ЦПЭ): Система учета и мониторинга электроэнергии.
1.2. Потребитель: Пользователь системы, имеющий доступ к данным о потреблении электроэнергии.
1.3. Администратор: Пользователь с расширенными правами, отвечающий за управление пользователями и данными.
1.4. Оператор: Пользователь, отвечающий за управление реле и мониторинг текущей информации.
1.5. База данных (БД): Упорядоченный набор структурированной информации или данных, которые обычно хранятся в электронном виде в компьютерной системе.

Описание взаимодействия системы с внешними компонентами:
	•	со стороны датчиков:
	•	Данные с датчиков (вольтметр, амперметр, реле) передаются на микроконтроллер ESP32.
	•	Данные с ESP32 передаются по wi-fi на нашу платформу по заданному адресу в указанных в Таблице 1 форматах.
	•	Данные из системы загружаются в СУБД PostgreSQL.

	•	со стороны пользователя:
	•	Пользователь заходит в систему и авторизуется. Пользователь взаимодействует с системой.
	•	Система делает Select-запросы на языке SQL к СУБД PostgreSQL. Далее возвращает результаты выполнения запроса пользователю: выводит данные о его потреблении за выбранный промежуток времени.

	•	со стороны администратора:
	•	Администратор заходит в систему и авторизуется.
	•	Система делает Select-запросы к базе данных  на языке SQL к СУБД PostgreSQL и выводит результаты администратору.

	•	со стороны оператора:
1) Оператор заходит в систему и авторизуется. Оператор взаимодействует с системой.
2) Система делает Select-запросы к базе данных  на языке SQL к СУБД PostgreSQL и выводит результаты оператору.
3) Оператор взаимодействует с системой, выбирает, какие реле должны быть включены/выключены и система отправляет исполнительную команду на включение/выключение реле на ESP32.

2.2. Интерфейсы системы
Для связи СУБД с разрабатываемой платформой будет использована библиотека psycopg2. Это библиотека для языка программирования Python (этот язык был выбран для разработки платформы).
Для связи датчиков с платформой будет использована библиотека requests языка программирования Python.
Для проверки логина и пароля пользователя будет создан запрос по следующему шаблону:
select login, password from users
where login=’login_value’ and password=’password_’;

Для проверки существования введённого пользователя будет создан запрос по следующему шаблону:
select login from users
where login=’login_value’;

Для добавления в БД записи о новом пользователе будет создан запрос по следующему шаблону:
INSERT INTO users(fio, login, password)
VALUES(‘new_fio’, ‘new_login’, ‘new_password);

[REQ-SYS-005]

4. Системные требования. 
4.1. Взаимодействие с датчиками: 
[REQ-SYS-012]
Система должна принимать данные с датчиков о потреблении (сила тока, напряжение) всегда, когда запущен сервер, и записывать их в базу данных. Датчики отправляют данные раз в 10 секунд в систему.  
4.2. Регистрация:

[REQ-SYS-013]
Система должна предоставлять возможность создать учетную запись пользователя. Пользователь заполняет все предложенные  системой поля, система должна проверить уникальность логина. Если он уникален, система создает новую учетную запись. В противном случае система должна отправить пользователю уведомление о том, что его логин не уникален. 

4.3. Авторизация:
[REQ-SYS-014]
Система должна предоставлять пользователю возможность авторизоваться с помощью логина и пароля. При успешной авторизации система должна перенаправить пользователя на главную страницу. В противном случае система должна отправить пользователю уведомление о том, что его логин/пароль неверные. 

4.4. Потребитель: 
	4.4.1. Просмотр информации о потреблении
[REQ-SYS-015]
4.4.1.1. Система должна рассчитывать стоимость электроэнергии за выбранный пользователем период (1/7/30 дней), исходя из значений потребления (сила тока, напряжения, время) и тарифов, которые лежат в БД. Тарифы вносит администратор вручную в базу данных, они одинаковы для всех. Напряжение, время и сила тока - данные с датчиков. 
[REQ-SYS-016]
4.4.1.2. Система должна выводить рассчитанную стоимость и тариф.
[REQ-SYS-017]
4.4.1.3. Система должна строить график зависимости мощности (сила тока умноженная на напряжение) от времени за выбранный промежуток времени. Данные о силе тока и напряжении лежат в БД.
4.4.2. Генерация отчетов 
[REQ-SYS-018]
4.4.2.1. Система должна рассчитывать стоимость электроэнергии за выбранный пользователем период (1/7/30 дней), исходя из значений потребления (сила тока, напряжения, время) и тарифов, которые лежат в БД. Тарифы вносит администратор вручную в базу данных, они одинаковы для всех. Напряжение, время и сила тока - данные с датчиков. 
[REQ-SYS-019]
4.4.2.2. Система должна генерировать отчет за выбранный пользователем период в формате PDF-файла, где будут указаны: суммарная стоимость потребленной энергии за выбранный период, график истории потребления и тариф. 
4.5. Администратор:
	4.5.1. Просмотр списка пользователей
[REQ-SYS-020]
Система должна предоставлять администратору список потребителей с указанием их логинов. Данные о потребителях хранятся в базе данных. 
4.5.2. Изменение ролей пользователей
[REQ-SYS-021]
Система должна предоставлять администратору возможность редактирования роли пользователя. После изменения значения поля система должна изменить роль пользователя в системе и обновить данные о пользователе в БД. 
	4.5.3. Просмотр данных о пользователей
[REQ-SYS-022]
Аналогично п.3.4.1., только система также должна предоставлять администратору возможность выбрать пользователя, у которого необходимо просмотреть информацию.
	4.5.4. Генерация отчета о пользователе
[REQ-SYS-023]
Аналогично п.3.4.2., только система также должна предоставлять администратору возможность выбрать пользователя, у которого необходимо сгенерировать отчёт.
4.6. Оператор:
4.6.1. Ручное управление реле:
[REQ-SYS-024]
Система должна предоставлять оператору возможность включать и выключать реле путём выбора реле для включения/выключения, после чего система должна послать сигнал на реле.


4.6.2. Просмотр информации о каждом потребителе:
[REQ-SYS-025]
4.6.2.1. Система должна предоставлять оператору возможность просматривать текущую информацию с датчиков каждого потребителя (сила тока, напряжение, состояние реле).
[REQ-SYS-026]
4.6.2.2. Система должна выводить актуальные данные после нажатия на кнопку “обновить”.
[REQ-SYS-027]
4.6.2.3. Система должна рассчитывать потребляемую каждым потребителем мощность (сила тока умножить на напряжение) и также выводить эту информацию.

6. Требования к базе данных
[REQ-BD-001]
Данная система должна хранить в себе следующие данные: логин, пароль, ФИО всех пользователей, статус оплаты (оплачено, не оплачено), данные с датчиков (сила тока, напряжение) потребителей, время сбора данных с датчиков, информация о реле (за каким пользователем закреплено реле, включено/выключено), роль пользователя (потребитель, оператор, администратор), тарифы на стоимость электроэнергии, дата назначения тарифа. 

[REQ-BD-002]
В базе данных должны содержаться следующие сущности и их атрибуты:
	•	Пользователь: логин, пароль, ФИО, роль
	•	Состояния реле: id реле, состояние (включено/выключено)
	•	Данные с амперметра: id амперметра, сила тока, дата_время
	•	Данные с вольтметра: id амперметра, напряжение, дата_время
	•	Тарифы: id тарифа, значение, дата добавления
