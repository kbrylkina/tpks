# LaTeX-шаблон для документов ТПКС — дизайн

Дата: 02.10.2026. Одобрено пользователем в чате («сделай все маленький шаблон главное чтоб агенты все подтягивали»).

## Цель

Пять документов семестра пишутся в LaTeX по одному примеру и собираются в PDF одной командой. Агент любого участника сам ставит недостающие зависимости. Общие данные (проект, команда, термины) лежат в одном месте и подставляются в каждый документ автоматически.

## Решения

- Вид как у лучшей прошлой команды: без титульного листа. Первая страница: шапка (документ, проект, версия, дата, команда) и сразу содержание. Лист регистрации изменений в конце документа.
- Times New Roman 12 pt, интервал 1,15, поля 25/15/20/20 мм, абзацный отступ 1,25 см. Разделы 1, 1.1, 1.1.1; «Таблица N — …» над таблицей, «Рисунок N — …» под рисунком; номера страниц внизу по центру. Если Times New Roman нет, подставляются Liberation Serif, затем CMU Serif.
- Движок XeLaTeX. Сборка: `latexmk` + `xelatex`, если есть, иначе Tectonic.
- Markdown-документы отменяются: `docs/0N_*.md` → `docs/0N_*.tex`, `docs/glossary.md` → `docs/glossary.tex`.
- Готовые PDF коммитим в `pdf/`, чтобы открывать их на GitHub без LaTeX. Каждый коммитит только PDF своего документа.

## Файлы

| Файл | Что внутри |

## Команды шаблона

| Команда | Что делает |
|---|---|
| `\documentclass{tpks}` | Подключает шаблон |
| `\doctitle{…}`, `\docversion{N}`, `\docdate{ДД.ММ.ГГГГ}` | Данные документа для шапки |
| `\docauthors{…}` | Необязательно: авторы вместо всей команды |
| `\makeheader` | Шапка и содержание, затем новая страница |
| `\begin{req}{SYS_04_02}{1} … \end{req}` | Требование: печатает «SYS_04_02; #1», текст, поля. ID проверяется по схеме `SYS|SRD_NN_NN`; повтор ID в документе — ошибка сборки |
| `\reqsource{…}`, `\reqnote{…}` | Внутри `req`: «Источник: …», «Комментарий: …» |
| `\reqref{SYS_04_02}` | Ссылка на требование (кликабельна, если оно в этом же документе) |
| `\printterms{ЕК, СП, ЗИ}` | Определения выбранных терминов из `glossary.tex`; нет термина — красная пометка и предупреждение |
| `\printallterms` | Весь глоссарий |
| `\clarify{…}` | Красное «[уточнить: …]» |
| `\begin{tabl}{|l|X|}{Подпись}[tab:метка] … \end{tabl}` | Таблица на всю ширину, может переходить на следующую страницу |
| `\begin{changelog} \change{версия}{дата}{что}{кто}{основание} \end{changelog}` | Лист регистрации изменений |

## Сборка и зависимости

`build.sh` (bash; на Windows — Git Bash):
1. Есть `latexmk` и `xelatex` → `latexmk -xelatex`, временные файлы в `docs/build/`, PDF в `pdf/`.
2. Иначе есть `tectonic` → `tectonic --outdir ../pdf`.
3. Иначе печатает команды установки Tectonic для macOS, Windows и Linux и выходит с кодом 2.
4. `ENGINE=tectonic` или `ENGINE=latexmk` выбирает движок принудительно.
5. При ошибке печатает строки ошибки из лога. Если не хватает пакета, подсказывает `tlmgr install` (нужен `sudo` — агент просит человека выполнить `! sudo tlmgr install …`) или сборку через `ENGINE=tectonic`.

## Проверка

- `./build.sh` собирает пример без ошибок через latexmk (BasicTeX) и через Tectonic.
- Повтор ID и ID не по схеме останавливают сборку понятной ошибкой; неизвестный термин даёт красную пометку.
- Сборка с несуществующим пакетом печатает подсказку про `tlmgr` и Tectonic.
- Субагент в роли участника команды по `AGENTS.md` пишет кусок документа и собирает PDF.

## План работ

1. `docs/tpks.cls`, `project.tex`, `glossary.tex`, `00_example.tex` — собрать пример через latexmk.
2. `build.sh`, `.gitignore` — проверить ошибки: повтор ID, ID не по схеме, нет пакета.
3. Tectonic (`brew install tectonic`) — собрать тот же пример.
4. Инструкции: `AGENTS.md` (сам), `README.md`, `docs/README.md`, TL;DR (субагент параллельно).
5. Субагент-участник пишет кусок документа по `AGENTS.md` и собирает PDF; исправить найденное, коммит, push, память.
